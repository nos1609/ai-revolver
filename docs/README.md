# Документация ai-revolver

Этот индекс отделяет действующие инструкции от датированных исследований и
планов. Положение файла в `docs/` само по себе не делает его описанием текущей
версии.

## Иерархия действующих документов

| Приоритет | Документ | Назначение |
|---:|---|---|
| 1 | [`DOCUMENTATION_STANDARD.md`](DOCUMENTATION_STANDARD.md) | Язык, структура и проверка документации. |
| 2 | [`architecture/overview.md`](architecture/overview.md) | Компоненты, данные и границы ответственности. |
| 3 | [`security.md`](security.md) | Модель угроз, хранение credentials и опасные операции. |
| 4 | [`operations/profile-lifecycle.md`](operations/profile-lifecycle.md) | Захват, переключение, sync, перенос и откат профиля. |
| 5 | [`troubleshooting.md`](troubleshooting.md) | Диагностика по наблюдаемым симптомам. |
| 6 | [`releasing.md`](releasing.md) | Проверка, версия, tarball и внешняя публикация. |
| 7 | [`source-attribution.md`](source-attribution.md) | Происхождение provider-контрактов и внешних решений. |

При конфликте фактическое поведение определяют код, provider manifest и тесты
текущего коммита. Действующую документацию нужно исправить в том же изменении.
Датированный отчёт не может молча изменить контракт команды.

## Исторические материалы

`superpowers/specs/` и `superpowers/plans/` содержат проектные решения и планы
конкретных волн. Они объясняют происхождение поведения, но не заменяют README,
актуальную архитектуру и `--help`.

`notes/` содержит датированные исследования внешних CLI. Такие документы могут
описывать старую версию поставщика. Перед изменением provider manifest нужно
повторить безопасную проверку на актуальной версии и очистить evidence от
credentials, персональных данных и локальных путей.

[`usage-probes-todo.md`](usage-probes-todo.md) — план, а не обещание текущей
поддержки. Фактическую возможность `usage` определяют manifests в `providers/`
и таблица в README.

## Проверка

Из корня репозитория:

```bash
npm run docs:check
npm run check
npm run build
npm pack --dry-run
git diff --check
```

`docs:check` проверяет обязательные документы, локальные Markdown-ссылки,
Mermaid fences и базовые сигнатуры чувствительных данных в отслеживаемых
файлах. Перед публичной публикацией нужна отдельная проверка всей Git-истории.
