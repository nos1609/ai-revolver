# Стандарт документации ai-revolver

## Назначение

Этот документ задаёт структуру и критерии проверки публичной документации
`ai-revolver`. Русский README и русские действующие документы являются
основными. `README.en.md` передаёт тот же смысл для англоязычного пользователя.

Команды, пути, API, поля данных, provider names и официальные названия
технологий не переводятся.

## Основные правила

- Сначала указывать назначение, влияние и границы, затем реализацию.
- Описывать фактическое поведение текущего кода. Планы отмечать отдельно.
- Давать команды из корня репозитория или явно называть другой каталог.
- Не делать путь конкретной рабочей станции частью инструкции.
- Не помещать credentials, персональные данные и необработанные evidence в Git.
- Не заявлять о готовности по старому тесту, локальному build или наличию файла.
- Разделять локальную проверку, commit, push, изменение visibility, release и
  публикацию npm как разные действия.
- Для опасной команды указывать условие, проверку результата и откат.
- Не дублировать внутренности provider CLI, если достаточно зафиксировать
  входной файл, выход и ограничение совместимости.

## README

README должен отвечать на вопросы:

1. Что делает проект и чего он не делает.
2. Какие платформы и provider manifests поддерживаются.
3. Где хранятся metadata и credentials.
4. Как установить из исходников и tarball на Linux, macOS и Windows.
5. Как выполнить первый `grab`, безопасный `switch` и rollback.
6. Какие команды делают сетевые запросы.
7. Как проверить код и пакет.
8. Где находятся security, troubleshooting, release и подробная архитектура.
9. Какова лицензия и граница аффилированности с поставщиками.

Русский и английский README обновляются вместе. Перевод может использовать
естественные термины языка, но не должен менять требования или обещания.

## Действующие и исторические документы

`docs/README.md` является картой. Он явно разделяет:

- действующую архитектуру;
- рабочие инструкции;
- security и release rules;
- датированные исследования;
- проектные планы;
- открытые задачи.

Исторический документ сохраняет дату и контекст. Его можно очистить от
чувствительных данных без сохранения исходного секрета или персонального
идентификатора.

## Команды и placeholders

- Использовать `<provider>`, `<name>` и `<version>` только как явно обозначенные
  placeholders.
- Не подставлять реальный email как имя профиля; использовать
  `profile@example.test` или нейтральные `work` и `personal`.
- Для PowerShell использовать PowerShell paths и syntax, для POSIX — Bash.
- Не смешивать `\` и `/` в одной команде.
- Перед публикацией выполнять команды из документа на поддерживаемой платформе.

## Mermaid

- Архитектурные схемы хранятся как fenced block `mermaid` в Markdown.
- Подписи в русских документах пишутся по-русски; точные имена команд и файлов
  сохраняются.
- После `<br/>` используется `&nbsp;`, чтобы строки не склеивались при копировании.
- Схема показывает зону ответственности и движение данных, а не декоративные
  детали.
- Изменённую схему нужно отрисовать в Mermaid renderer до commit.

## Безопасность

В отслеживаемых документах запрещены:

- access, refresh, API и enrollment tokens;
- private keys, passwords и содержимое `vault.enc`;
- plaintext export `airev`;
- полный opaque credential blob;
- персональный email, username или обязательный абсолютный home path;
- необработанные provider API responses, если они могут содержать identity.

Допустимы имена переменных, условные значения `example.test`, безопасные
структуры данных и очищенные результаты проверок.

## Проверка перед commit

1. Сверить текст с кодом, manifests, `package.json` и `airev --help`.
2. Выполнить `npm run docs:check`.
3. Выполнить `npm run check` и `npm run build`.
4. Проверить `npm pack --dry-run` и состав архива.
5. Выполнить `git diff --check`.
6. Проверить, что индекс Git не содержит локальных recovery scripts и exports.
7. Перед первой публичной публикацией проверить всю публикуемую Git-историю
   отдельным secret scanner с redaction.

Автоматическая проверка не заменяет редакторский проход и проверку команд на
Windows, Linux и macOS в объёме заявленной поддержки.
